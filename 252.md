### What changed
**Server**
- The indexer keeps a count of assets walked and the total for each library while a walk runs: `indexer.index_progress(id)`. It's in memory only, updated every 100 assets, and cleared when the walk ends, including when it fails.
- `GET /api/admin/libraries/{id}/status` returns `index_progress: {done, total}` while `index_state` is `indexing`, and `null` otherwise.

**Admin → Libraries**
- Every row loads its status as soon as the page opens. The "Load status" button is gone.
- A row shows one of:
  - **Indexing… 1,234 of 52,000 photos**, with a progress bar;
  - **Ready — 52,000 photos**;
  - **Indexing failed: …**, with the reason in plain words and a hint to press Re-index.
- Light polling: every 2 s, only for libraries that are indexing or not indexed yet. It stops by itself once none are left. A library that was just added is polled too, because its background job hasn't marked it "indexing" yet.

⚠️ The walk takes `list(photosdb.photos())` to know the total. osxphotos already returns a list, so this doesn't use more memory for real libraries. Only test fakes that yield photos one at a time are affected.
