Fixes #257. **Base: `fix/267-viewer-fit-zoom-pan`** (stacked; that PR is based on `feat/filmstrip-221`). Retarget this to `feat/filmstrip-221` once #267's PR merges.

### Cause
The desktop still's inline cursor was `scale > 1 ? "grab" : "zoom-in"`, and nothing changed it while the mouse button was held. So you got the zoom cursor at fit and during drags at fit, and the open hand never closed. The cursor was also set only on the still, so as soon as a drag crossed the top bar or the filmstrip, those elements' own cursors showed.

### Fix (`DesktopViewer.tsx`, `shell.css`)
| State | Cursor |
|---|---|
| At fit, hovering | default arrow (there's no single-click zoom; double-click zooms) |
| Zoomed (can pan), hovering | `grab` |
| Zoomed, button held | `grabbing` from mousedown |
| At fit, dragging to page or dismiss ([#267](https://github.com/pislagz/apple-photos-app/issues/267)) | `grabbing` once the drag starts (8 px axis lock), so a click or double-click never flashes it |
| Any drag, pointer over the top bar or filmstrip | `grabbing` (the root gets `.is-dragging`) |

The zoom cursor no longer appears anywhere in the viewer.

### Tests
- `DesktopViewer.test.tsx` "cursor (#257)": arrow at fit, including on mousedown; grabbing once a fit drag moves; grab when zoomed; grabbing while held and back to grab on release; `.is-dragging` on the root; the CSS rule; no `zoom-in` left in the file.
- `e2e/viewer-fit.e2e.ts` (desktop) reads the real computed cursor under the pointer in Chromium. It checks the arrow at fit, grab when zoomed, grabbing on mousedown, grabbing while the drag crosses the top bar, and grab after release. It passed against the Vite dev server with a mocked `/api`, and against the real `scripts/dev_demo.py` demo built from this branch (all viewer-fit tests pass there).
- vitest 591/591, `tsc`, and `check-colours` pass.

⚠️ No screenshot, because headless Chromium screenshots don't render the mouse cursor. The e2e reads `getComputedStyle(elementFromPoint(...)).cursor` instead. Measured values:
`{"fitHover":"default","zoomedHover":"grab","zoomedButtonDown":"grabbing","dragOverFilmstrip":"grabbing","dragOverTopbar":"grabbing","afterUpOnPhoto":"grab"}`

⚠️ [#255](https://github.com/pislagz/apple-photos-app/issues/255) (arrow cursor everywhere) is on its own branch off `main`, and its `cursors.test.ts` only forbids `cursor: pointer`. `grab` and `grabbing` don't conflict with it.
