Fixes #265.

### Cause (on main)
The first click selects the tile and sets `focusedId`. An effect then called `rowVirtualizer.scrollToIndex(row, { align: "auto" })` for **every** focus change, mouse clicks included. When the clicked tile was partly off-screen (top or bottom row), the grid scrolled under the pointer. The second click then landed on a different element, so the browser didn't count it as a double-click, which matches "once it took three tries". Each selection change also re-rendered every tile and its `<img>`.

### Fix
1. **No scroll on click.** Clicked tiles are already under the pointer, so the scroll-into-view now runs only for keyboard focus moves (arrows, Enter after load, Cmd+A paths).
2. **Our own double-click detection.** A second plain click within 500 ms, **on the same tile or within 6 px of the first click**, opens the photo from the *first* click. That makes it robust even if something else shifts the layout between the clicks. The browser's native `dblclick` still works as a fallback, for example for synthetic events and assistive tech, and is de-duplicated so the viewer never opens twice. Shift, Cmd, Ctrl and Alt clicks never count toward a double-click.
3. **Stable tiles.** Tiles are a memoised `GridCell` with stable callbacks, so a selection change re-renders only the tiles whose `selected` flips. Images aren't re-rendered or re-decoded.

### Tests (`DesktopLibrary.test.tsx`, "double-click reliability (#265)")
- Two clicks on an **unselected** tile open the viewer on that photo, without any native `dblclick`.
- Two clicks at nearly the same spot on *different* tiles (simulating a re-layout) open the first photo.
- Two clicks on far-apart tiles only select.
- A native `dblclick` right after our detection doesn't reopen the viewer.
- Selecting a tile keeps every tile **and** `<img>` element identical (no remount).
- A click doesn't call the grid's `scrollTo`.

Against main's `DesktopLibrary.tsx`, 4 of these 6 fail (the first four plus the scroll one). The remount test passes on main as well: tiles weren't actually remounting there, it's a guard. The full suite (496) and `tsc` pass.

### ⚠️⚠️⚠️ The black flash on `feat/filmstrip-221` isn't verified
On **main** tiles don't remount on selection (the new test proves it), so the "all grid images flash black" part must come from something on the viewer stack ([#245](https://github.com/pislagz/apple-photos-app/pull/245)–[#248](https://github.com/pislagz/apple-photos-app/pull/248)), probably the open/close zoom from [#247](https://github.com/pislagz/apple-photos-app/pull/247) hiding or replacing tiles. With this PR a failed double-click no longer happens, so that path shouldn't trigger anymore. Please re-check the flash after rebasing the stack onto this. If it still flashes, it's a separate bug in #247.
