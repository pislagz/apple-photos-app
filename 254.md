Fixes #254.

### What changes
- **Server:** `GET /api/libraries/{id}/assets` (and the other routes that return the same list items) now include `is_heic`. It comes from the **original's UTI** (`public.heic`, `public.heif`, `public.heics`, `public.heifs`), falling back to `uti` and then to the `.heic`/`.heif` extension for rows indexed before the UTI columns existed. A `.HEIC`-named file whose UTI says JPEG counts as **not** HEIC.
- **Web:** `selectionHasHeic(items, selectedIds)` decides whether to show the "HEIC as JPEG" checkbox in `ZipStatus`. This applies on desktop (toolbar) and phone (select bar). A selected id that isn't in the loaded items, or an item from an older server without `is_heic`, counts as "might be HEIC": showing the option once too often is harmless, hiding it when it matters is not.
- When the selection has no HEIC, the zip is always requested as `native`, even if the checkbox was ticked earlier for another selection. That keeps the size estimate exact instead of "about".
- The D50 `HeicFallbackModal` flow is unchanged.

### Tests

- Web: unit tests for `selectionHasHeic`, `ZipStatus` hiding the checkbox, and a `MobileLibrary` test where the checkbox appears only once a HEIC photo is selected. The full web suite and `tsc` pass.
