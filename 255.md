Fixes #255.

### Cause
37 controls in `shell.css` and 3 in `admin.css` set `cursor: pointer`, while their containers, the gaps between them and some inner elements (labels, the layout select in the account menu, `summary` rows) kept the arrow. Moving across a menu crossed those boundaries constantly, so the cursor flickered.

### Fix: one rule, the Photos one
- Every `cursor: pointer` is now `cursor: default`.
- A base rule at the top of `shell.css` gives the arrow to `button`, `summary`, `label`, `select`, checkboxes and radios, `[role=button|menuitem|menuitemradio|option|tab]`, and links inside the account menu. The whole hit area of a control now has one cursor.
- **Links in running text** (OSM attribution, links in Admin text) keep the browser's hand, which is still the platform convention for real links.
- The viewer's `grab`/`zoom-in` cursors are untouched. They're handled in #257.

### Tests
- `src/cursors.test.ts` (runs in `npm test` and CI) fails if any stylesheet under `src/` sets `cursor: pointer` again, and checks that the base rule covers menu items and tabs.
- `e2e/polish.e2e.ts` adds the Playwright check the issue asked for. On desktop it samples 15 points across every account-menu row (edges, padding, label) and across toolbar/sidebar buttons, and asserts a single computed cursor, `default`.

### Playwright, run against the demo server (`scripts/dev_demo.py --build`)
`e2e/polish.e2e.ts` passes in all projects: 14 passed, and 7 are skipped by design (desktop-only tests in the phone projects and vice versa). The first run caught a false failure in the new test. Its edge sample points landed in the rounded corners of the toolbar buttons, i.e. on the toolbar strip behind them (`cursor: auto`, which is drawn as the same arrow). The test now requires the arrow for every point inside a control, and for points that miss only requires that the cursor isn't the hand.
